# Lesson 13: Review analytics and understand product performance

**Verification:** sample numbers were entered and read back live (VERIFIED). **Sample numbers only; none are real sales.** CSV import and Gumroad sync were not run.

## Learning objective
Enter real evidence, read it without mixing sources, and treat recommendations as suggestions.

## What we are creating
A set of sample performance numbers for one recorded listing.

## What we need
A listing recorded as published ([Lesson 12](12-export-or-publish.md)).

## Steps
1. **Analytics** → **Enter numbers manually**. Choose the listing.
2. Enter three metrics for the same period (for example 1 to 15 November): **views** 240, **orders** 6, **revenue in cents** 2394. For each choose "Real (copied from my shop stats)".
3. **Save** each.
4. Press **Refresh recommendations**.
5. Read **Production (last 30 days)**: versions produced, QA failure rate by type, review decisions.

## Expected results (live)
- *Sales and engagement by source:* **Entered manually**: Orders 6, Revenue $23.94, Views 240.
- *By product:* a row for the mandala with 6 orders, $23.94, 240 views.
- *Production:* 23 versions produced, average time to review-ready 0.1 minutes, QA failure rate by type (Daily planner 1/3).
- *Recommendations:* none until there is enough evidence.

## What to inspect
Is the source label right (real or estimate)? Did you enter *cents* for revenue? Do the production numbers tell you where QA fails most often?

## Common mistakes
Entering dollars as cents; calling an estimate real; adding Etsy and Gumroad together (the page never does).

## Completion criteria
- [ ] Numbers entered with the right source.
- [ ] I can read the by-product table.
- [ ] I treat recommendations as suggestions.

## What I learned
Foundry shows only the evidence you give it, by source. It never combines sources or invents a number.
