# Digital Asset Factory — Product Specification

## 1. Purpose

Digital Asset Factory (DAF) is a local-first application that manufactures commercial digital
products (printables, activity sheets, spreadsheets, bundles) and prepares them for sale on
marketplaces. It runs on the seller's own computer, keeps all data locally, produces products on
a schedule, and **never publishes anything without a recorded human approval**.

It optimizes for *revenue-relevant, differentiated, compliant* products — not raw volume. Volume
is bounded by configurable quotas, cost limits, QA gates, duplicate detection and opportunity
thresholds.

## 2. Users and usage

A single operator (shop owner) on one machine. Typical day:

1. The scheduler runs the daily production plan overnight (or when the app next starts).
2. In the morning the operator opens **Batch Approval**, inspects previews, QA results, scores and
   listing drafts, then approves, rejects, edits, regenerates or returns items for revision.
3. Approved items get marketplace export packages (and, once a verified API adapter exists,
   direct publication).
4. The operator records publication status and imports sales/performance data; the analytics
   module turns that evidence into recommendations the operator can accept or dismiss.

No terminal commands are needed for ordinary work once the app is running.

## 3. Product families and initial product types

Each product type is a **plugin** (`src/engine/producttypes/*`) declaring its own parameters,
content schema, generation steps, renderer, QA profile and listing hints. Adding a format means
adding a plugin; the pipeline does not change.

| Family | Product type id | Deliverables | Content source |
|---|---|---|---|
| Printable | `monthly-calendar` | PDF (one page per month) | Deterministic dates; AI theme copy/quotes optional |
| Printable | `weekly-planner` | PDF (dated weeks) | Deterministic dates; AI focus prompts |
| Printable | `daily-planner` | PDF (dated or undated days, time blocks) | AI prompts/sections; deterministic layout |
| Printable | `habit-tracker` | PDF (monthly grids) | AI habit suggestions per audience |
| Printable | `todo-checklist` | PDF | AI checklist items for a theme (e.g. moving house) |
| Printable | `cleaning-schedule` | PDF | AI tasks by room and frequency |
| Printable | `home-inventory` | PDF + CSV + XLSX | AI room/category columns |
| Printable + structured | `budget-planner` | PDF + XLSX (formulas) + CSV | AI category set per audience |
| Printable + structured | `invoice-template` | PDF + XLSX (formulas) + CSV | Deterministic business form |
| Printable | `guided-journal` | PDF | AI journal prompts |
| Printable | `goal-planner` | PDF | AI goal-setting prompts |
| Coloring / activity | `mandala-coloring` | PDF + PNG + SVG | Procedural seeded SVG line art (no AI required) |
| Coloring / activity | `maze-activity` | PDF (puzzles + answer key) + SVG | Procedural seeded mazes |

Structured assets (CSV, XLSX, ZIP, license and instruction documents) are produced by the
packaging module for every product that declares them.

### Generation policy: AI-first with a deterministic path

- When an AI text provider is configured, content (titles, prompts, checklist items, habit lists,
  word lists, listing copy) is generated by AI using **schema-validated structured output**.
- When it is not configured, the operator chooses (Settings → Generation) between failing the job
  (`fail`) or using the built-in deterministic content libraries (`deterministic`, default). The
  product's provenance always records which generator produced every asset, and the UI shows a
  persistent banner while AI is unconfigured.
- Image AI is used only by product types that need illustration (`illustrated-coloring`).
  Geometric/line-art, mazes, calendars and planners never depend on an image provider.

## 4. Lifecycle

```
Opportunity discovery → Opportunity evaluation (scoring) → Product specification
 → Content generation → Visual generation → Rendering → Quality assurance → Packaging
 → Listing preparation → Batch approval → Publishing / export → Performance tracking
```

Each product type declares which stages it uses (e.g. `invoice-template` skips visual generation;
`mandala-coloring` skips AI content). Stages run as durable background jobs.

### Rejection, revision, retry, recovery

| Situation | Behavior |
|---|---|
| Transient failure (timeout, 429, 5xx, Chrome crash) | Job retried with exponential backoff up to `max_attempts`; each attempt recorded |
| Permanent failure (invalid spec, invalid model output after retries, missing credential) | Job marked `failed` with an actionable message; operator can fix settings and retry |
| QA hard failure | Version → `qa_failed`; cannot be approved; operator can regenerate or edit |
| Operator **rejects** in batch | Decision recorded; version is never published; product may be archived |
| Operator **returns for revision** | New version created with the revision notes fed into generation |
| Operator **regenerates** | New version with a new seed; previous version kept for history |
| Operator **edits** content or listing after approval | If the change alters the approved deliverable or listing fingerprint, approval is invalidated automatically |
| App closed / crash mid-job | On restart, stale `running` jobs are marked interrupted and re-queued; scheduler resumes overdue plan runs without duplicating them |

## 5. Opportunity research and scoring

- Research observations come from manual entry, CSV import (e.g. keyword tools, marketplace
  exports), and AI-suggested ideas. **The app does not scrape marketplaces.**
- Every numeric value carries an **evidence kind**: `measured`, `external_estimate`,
  `model_hypothesis`, or `unknown`. AI suggestions are always `model_hypothesis`.
- The score combines eight factors (demand, competition, differentiation, commercial potential,
  production cost/effort, bundle potential, seasonality/timing, quality & policy risk) with
  configurable weights. Unknown factors are excluded from the weighted score and lower the
  **evidence confidence**. Thresholds are configurable starting points, displayed as such.
- The app never fabricates search volume, competitor sales, demand or projected revenue.

## 6. Publishing model

The app distinguishes five operations: **generate listing**, **prepare export package**,
**publish**, **update listing**, **record publication status**.

- Minimum release: functional **export packages** for Etsy, Gumroad and a generic catalog, each
  with files, images, listing text and step-by-step manual publishing instructions.
- Publication status is either `published_verified` (confirmed by an API adapter) or
  `published_manual` (recorded by the operator; shown as *not verified by the app*).
- Direct API adapters for Etsy and Gumroad are designed behind the adapter interface but report
  `not_implemented` until built and verified against real credentials (see
  SECURITY_AND_PUBLISHING.md).

## 7. Minimum complete release (MCR)

1. Local server + SQLite persistence + asset store, one-command install and start; restart-safe.
2. Browser UI with all screens listed in ACCEPTANCE_CRITERIA.md showing persisted data only.
3. All product types in §3 except `illustrated-coloring` producing validated deliverables
   without AI; `illustrated-coloring` working when an image provider is configured.
4. Anthropic text provider (structured output, retries, timeouts, usage/cost tracking) and
   OpenAI image provider behind the provider abstraction; deterministic/procedural fallbacks.
5. Automated QA with hard failures vs. warnings, enforced at approval and publish time.
6. Daily production scheduler with quotas, rotation, cost limits, resume and dedupe.
7. Batch approval bound to exact version + destination with invalidation on material edits.
8. Export-package publishing for Etsy, Gumroad and generic; manual status recording.
9. Research, scoring, analytics (CSV import + manual entry), recommendations.
10. Backup/restore, structured logs, audit trail, secure credential storage.
11. Optional desktop window (Chrome app mode launcher; Electron shell as optional install).

## 8. Later extensions

- Verified Etsy API adapter (OAuth PKCE, draft → files → images → activate) and Gumroad adapter
  once credentials are available for verification.
- Additional text providers (OpenAI, local Ollama) and image providers (local diffusion servers).
- Mockup scene rendering, A/B listing experiments, multi-language products.
- Print-shop CMYK output (requires a non-Chromium PDF pipeline; Chrome produces sRGB only).
- Multi-user / remote access (deliberately out of scope: the server binds to localhost only).
